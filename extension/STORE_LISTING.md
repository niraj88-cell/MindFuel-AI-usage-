# Chrome Web Store — submission kit (SatyaShift)

Everything needed to publish, so the upload itself takes ~15 minutes. The store build
zip is generated by the packaging step below (it strips the localhost dev entries from
the manifest; the repo manifest keeps them for local development).

## 2. Permission justifications (paste into the "Privacy practices" tab)

- **tabs** — Needed to know which site the active tab is on, so time can be counted
  per site. The extension reads the tab's address only to extract the bare domain
  (e.g. "github.com"); the full address, page title, and content are never stored or
  transmitted.
- **cookies** — Used only to read the sign-in session for satyashift.vercel.app (the
  extension's own companion app), so your focus time syncs to your own account. Host
  access is limited to that one site; the extension cannot read cookies from any
  other website.
- **storage** — Keeps the extension's own state (your session timer, the queue of
  time entries waiting to sync) on your device, so nothing is lost if the browser
  restarts.
- **alarms** — A once-a-minute timer that keeps time counting and check-ins working,
  because Chrome puts background extensions to sleep.
- **idle** — Detects when you've stepped away or locked your screen, so time you
  didn't actually spend on a site is not counted. Honesty requires knowing when
  you're gone.
- **notifications** — Shows the one gentle check-in when attention has drifted for
  several minutes. Nothing else is ever shown.
- **Host permission (satyashift.vercel.app)** — The extension's only network peer:
  it syncs your per-domain time to your account and connects your sign-in. It talks
  to no other site.

**Single purpose statement:** Passively measures time spent per website domain and
verifies the user's own focus sessions, with an optional gentle notification when
attention drifts.

## 5. Packaging the store zip

From the repo root (PowerShell):

```powershell
$stage = "$env:TEMP\satyashift-store"
Remove-Item -Recurse -Force $stage -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force $stage | Out-Null
Copy-Item extension/background.js, extension/bridge.js, extension/core.js, `
  extension/popup.html, extension/popup.js, extension/welcome.html, `
  extension/icon16.png, extension/icon32.png, extension/icon48.png, `
  extension/icon128.png $stage
# Store manifest: same as the repo's, minus the localhost dev entries.
node -e "const m=require('./extension/manifest.json');m.host_permissions=m.host_permissions.filter(h=>!h.includes('localhost'));m.content_scripts[0].matches=m.content_scripts[0].matches.filter(h=>!h.includes('localhost'));require('fs').writeFileSync(process.env.TEMP+'\\satyashift-store\\manifest.json',JSON.stringify(m,null,2))"
Compress-Archive -Path "$stage\*" -DestinationPath "$env:TEMP\satyashift-store.zip" -Force
```

Tests, CLAUDE.md, package.json stay out of the zip on purpose.

## 6. Founder submission steps (~15 min + review wait)

1. https://chrome.google.com/webstore/devconsole → register developer account
   ($5 one-time, any Google account; use the founder account, not a throwaway).
2. "New item" → upload `%TEMP%\satyashift-store.zip`.
3. Fill Store listing tab from section 1, Privacy tab from sections 2–3, upload
   screenshots from section 4.
4. Distribution: Public, all regions, Free.
5. Submit for review. Reviews for tabs+cookies extensions typically take a few days
   to ~3 weeks. Respond quickly if the reviewer emails.
6. **After approval:** put the store URL into `web/lib/extension.ts`
   (`EXTENSION_STORE_URL`), flip `EXTENSION_PUBLISHED`, deploy. Onboarding and the
   dashboard connect card switch to "Add to Chrome" automatically.

```powershell
npx web-push generate-vapid-keys

npx vercel env add VAPID_PRIVATE_KEY production              # paste new private key

```
